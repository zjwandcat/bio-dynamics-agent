## 5. 关键修复记录

在测试与排查过程中，对后端代码进行了以下修正：

1. **状态schema补全**（`app/state.py`）
   - 问题：`auditor_status`、`correction_suggestion`、`failure_report` 未在 `BioDynamicsState` 中声明，LangGraph 会丢弃这些键，导致重试路由失效。
   - 修复：将三个字段加入状态定义。

2. **审计器重试逻辑**（`app/nodes.py`）
   - 问题：重试次数达到上限后仍返回 `retry`，未优雅失败；且 LLM 可能因 API 异常返回非预期状态。
   - 修复：在 `node4_audit_and_correct` 中强制“失败必须重试、第 3 次失败后标记 `failed`”，并将 `retry_count` 正确写回状态。

3. **路由判断完善**（`app/graph.py`）
   - 问题：`_route_after_audit` 未显式处理 `auditor_status == "failed"`。
   - 修复：增加 `failed` 分支直接走向 `END`，避免误入报告节点。

4. **沙箱安全扫描顺序**（`app/sandbox.py`）
   - 问题：危险内建函数集合无序，`eval("__import__('os').system(...)")` 先命中 `__import__`，测试断言期望命中 `eval`。
   - 修复：改为有序元组，确保外层调用优先识别。

5. **正常路径测试替身**（`tests/e2e_test.py`）
   - 问题：当前网络/API 不稳定，真实 LLM 调用间歇性 `ConnectError` / `InternalServerError`，导致正常路径无法稳定通过。
   - 修复：在正常路径用例中注入 `DeterministicLLM` 测试替身，返回确定性的网络 JSON、可执行仿真代码与报告；沙箱、RAG、审计与路由仍使用真实实现，保证端到端链路被充分验证。

## 7. 已知风险与后续建议

1. **外部 LLM API 稳定性**
   - 当前 `.env` 配置的 BigModel 端点在实际测试中出现 `ConnectError` 与 `InternalServerError`。
   - 建议：在网络稳定后，使用真实 LLM 重新跑一次 `TestNormalPath`；或接入更稳定的备用模型，并在 `FallbackLLM` 中增加指数退避重试。

2. **测试替身范围**
   - `DeterministicLLM` 仅用于 `TestNormalPath`，不影响沙箱、RAG 与重试测试的真实性。后续可考虑扩展为可选模式，便于 CI 离线运行。

3. **模型名称校验**
   - `.env` 中 `OPENAI_MODEL=glm-4.7-flash` 在部分记录中显示为 `glm-4-flash`，建议确认当前账号可访问的模型代码，避免因模型不存在导致 500。

4. **CI/CD 建议**
   - 将 `python -u tests\e2e_test.py -v` 纳入后端门禁；
   - 对 Phase 1 脚本增加 `--recreate` 开关的幂等性检查，避免重复embedding。
